# X AI 内容折叠（Chrome 插件）

浏览 X（x.com / twitter.com）时自动扫描已加载的帖子；进入帖子详情页时同时扫描回复。每条内容交给 [TypeSafe](https://typesafe.ai/) 的 Jev 模型判断是否由 AI 生成，AI 概率达到阈值的自动折叠，点“展开”即可查看。

## 安装

1. 打开 `chrome://extensions`，右上角打开“开发者模式”。
2. 点“加载已解压的扩展程序”，选择本项目里的 `extension/` 目录（如果拿到的是 zip，先解压，再选择解压后的目录）。注意不要选项目根目录 `x-ai-filter/`，否则 Chrome 会报“清单文件缺失或不可读取”。
3. 首次安装会自动打开设置页：在 [console.typesafe.ai/keys](https://console.typesafe.ai/keys) 创建 API Key，填进去后点“测试连接”。
4. 刷新已经打开的 X 页面。

## 工作方式

- **扫描**：页面脚本监听 DOM 变化，找到每条 `article[data-testid="tweet"]`，读取作者、正文（含 emoji）和引用帖内容，按帖子 ID 去重。滚动加载、单页跳转（时间线 → 详情页）都会自动处理。
- **回复的上下文**：在 `/status/<id>` 详情页，主帖下面的内容按“回复”处理，请求里会带上主帖作为 `replying_to`，Jev 可以据此识别“和原帖无关的万能回复”这类 AI 回复机器人。主帖上方的线程祖先按普通帖子处理。
- **判断**：后台 Service Worker 调用 `POST https://api.typesafe.ai/v1/systemone`，提 Noul（是/否）问题，读取每个问题的 `noul`（0–1 的“是”概率），取最高的一个作为 AI 分数。默认模型固定为 `jev-1.14.0`，这样阈值不会因为模型升级而漂移。
  - `ai_generated`（所有内容）：文字本身读起来像不像 LLM 写的。
  - `templated_reply`（只问详情页里的回复）：是不是套话式回复，即把原帖（或原帖截图里的东西）概括成一句漂亮的结论、照搬原帖的原话或梗、或者在复述原帖细节的基础上夸一句。AI 回复机器人的中文、英文都很通顺，单看文风常常只有 0.1–0.4，露馅的是它和原帖的关系，这个问题专门抓这一点。只有一句“恭喜，实至名归”这种短套话、没有复述原帖的，判为“否”，免得误伤朋友间的随手祝贺。
- **折叠**：分数 ≥ 阈值（默认 0.6）的内容被一条提示条替代，提示条写明是“AI 文风”还是“套话式回复”触发的、作者和分数，鼠标悬停可以看到每个问题的分数。可以展开或重新折叠，也可以改成“只标注，不折叠”。
- **诊断模式**：设置里打开“显示检测分数”后，每条内容上方都会显示分数，或者没检测的原因（太短、白名单、出错等），用来校准阈值和排查漏判。
- **省钱和限流**：每条帖子只请求一次，结果按“模型 + 帖子 ID”缓存在本地（最多 3000 条）；最多 4 个请求并发；遇到 429/529 按 `retry-after` 或指数退避重试；短于最短字数（默认 15）的内容直接跳过。Jev 按输入 token 计费，每百万 token 0.042 美元，弹窗里会显示本次会话的调用次数和大致费用。
- **API Key 失效**时停止发送请求，弹窗里显示错误；改好 Key 后自动恢复。

## 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 模型 | `jev-1.14.0` | 可选 `jev-latest`、`jev-1.13.0`，“测试连接”会拉取账号可用的模型 |
| AI 概率阈值 | 0.60 | 见下面的“阈值依据” |
| 命中后 | 折叠 | 或“只标注” |
| 扫描范围 | 帖子 + 回复 | 两项可以分别关闭 |
| 最短字数 | 15 | |
| 白名单 | 空 | 这些账号不检测 |
| 显示检测分数 | 关 | 诊断用 |
| API 地址 | `https://api.typesafe.ai` | 走自建代理时修改，保存时 Chrome 会请求该域名的权限 |

## 阈值依据

用真实的 `jev-1.14.0` 测过 5 组手写样本，共 75 条（`npm run eval:live` 可以重跑），阈值 0.6 时全部判对：

| 样本组 | 条数 | 真人最高 | AI 最低 | 说明 |
| --- | --- | --- | --- | --- |
| dev | 20 | 0.15 | 0.81 | 第一版问题时用的，某条中文帖子下的回复 |
| summary + echo | 12 | 0.11 | 0.91 | 第二种机器人套路（一句话总结截图内容 + 照搬原帖原话），以及长得像的真人回复 |
| holdout | 13 | 0.28 | 0.75 | 第一版写完后另写，第二版修改时看过 |
| holdout 2 | 16 | 0.28 | 0.62 | 第二版写完后另写；发现随手的祝贺被误判后据此收窄过 |
| holdout 3 | 14 | 0.46 | 0.74 | 最后写的，修改问题时没有用来调过 |

另外，措辞正式的真人帖子（产品发布公告、新闻快讯、系统维护公告、求职动态）只问文风问题，分数 0.17–0.53。

所以默认 0.6：再低会开始折叠正式的公告和新闻，以及带细节的真人祝贺（如 "congrats!! mile 20 is where everyone cries"，0.46）；再高会漏掉一部分 AI 回复。Jev 对同一条内容的分数每次会有几个百分点的浮动。样本都是手写的，数量也小，换到你自己的时间线上，建议打开“显示检测分数”看一阵再调。

只有文字会发给 Jev，图片不会。机器人回复常常是在概括原帖截图里的内容，所以“套话式回复”问题明确告诉 Jev：原帖可能带图，对产品或话题的高度概括即使原帖文字里没有，也算复述。

## 开发与测试

```bash
npm install
npx playwright install chromium   # 首次运行 e2e 需要
npm test                          # TypeSafe 客户端单元测试
npm run test:e2e                  # 在 Chromium 中加载插件，用模拟的 X 页面和模拟的 TypeSafe API 跑端到端测试
TYPESAFE_API_KEY=... npm run eval:live   # 用真实 Jev 给手写样本打分，检查问题和阈值（会产生少量费用）
npm run package                   # 打包 extension/ 为 x-ai-filter.zip
```

端到端测试覆盖：时间线折叠、引用帖不误伤、emoji 读取、短内容跳过、429 重试、展开/折叠、滚动加载、DOM 节点复用、阈值/标注模式/白名单/开关即时生效且不重复调用、详情页回复带主帖上下文并多问一个“套话式回复”问题、诊断模式、深色主题、设置页、错误 Key。

## 已知限制

- X 的页面结构没有公开约定，选择器（`data-testid="tweet"`、`tweetText`、`User-Name`）以后可能失效，失效时插件只会“什么都不折叠”，不会误隐藏。
- 自动化测试用的是模拟的 X 页面；页面结构照 X 的 `data-testid` 仿写，但没有在真实 x.com 上跑过自动化测试。
- 修改问题后要把 `typesafe.js` 里的 `QUESTION_VERSION` 加一，否则本地缓存里旧问题的分数会继续生效。
- AI 文本检测本身存在误判，尤其是很短的回复，所以折叠后随时可以展开。
- 被检测的帖子文本会发送给 TypeSafe。
- API Key 保存在本机的 `chrome.storage.local`。如果要把插件分发给别人，建议改为走自建代理，不要把 Key 打包进去。
